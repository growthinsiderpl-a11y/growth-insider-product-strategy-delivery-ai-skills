# Retention Diagnosis

Diagnose a retention problem inside the product experience and
propose minimum-sufficient next moves grounded in behavior and
evidence.

## When To Run It

- repeat usage is falling or plateauing
- new users activate but do not stick
- leaders need to separate product retention issues from
  acquisition noise
- teams are tempted to treat churn as one generic problem

## Do Not Run It When

- the issue is clearly lifecycle messaging owned by marketing
- retention is being treated as one global average with no
  cohorts
- the team wants a fake health score
- there is no shared definition of the value moment

## Inputs

- cohort data
- activation milestones
- segment splits
- qualitative feedback
- recent changes
- product value hypothesis

## Procedure

### Locate the Drop

- identify which cohort, segment, or stage is failing
- compare activation completion with repeat usage
- check whether the problem is immediate decay or later
  disengagement
- mark data quality issues
- state whether the loss appears user-side, account-side, or
  team-side

### Inspect the Value Loop

- state the expected recurring value moment
- ask whether users reach it repeatedly
- look for missing collaboration, data, habit, or trust
  conditions
- check if the product asks too much before value appears
- identify whether the loop depends on one brittle action or
  actor

### Triangulate with Qualitative Evidence

- use interviews, support notes, or observations to understand
  why users leave or reduce use
- look for mismatch between promised and experienced value
- capture contextual blockers outside the interface
- avoid assuming one narrative explains every cohort
- note where new evidence collection is still required

### Design Interventions

- propose changes tied to the diagnosed break point
- separate product changes from lifecycle communication follow-up
- prefer targeted interventions to broad redesigns
- define what success would look like
- state what should be tested before full investment

### Review Honestly

- set a measurement window
- identify guardrails such as support load or conversion impact
- record residual unknowns
- decide whether the team should deepen diagnosis before building
- capture which segments are intentionally not addressed yet

## Decision Tests

- the retention problem is cohort-aware
- the value loop is explicit
- interventions tie to the diagnosed break
- product and marketing retention work are separated
- unknowns are carried forward rather than hidden

## Outputs

- retention diagnosis memo
- cohort-specific intervention list
- evidence gaps
- measurement plan
- segment caveats for stakeholder communication

## Failure Modes

- blaming churn on price or competition without product evidence
- treating onboarding and retention as unrelated
- proposing generic engagement features with no diagnosis
- using cohort tables without explaining the product behavior
  behind them

## Review and Follow-through

- connect outcome to roadmap and experiment planning
- recheck cohorts after the intervention window
- share findings with marketing when lifecycle support is also
  needed
- capture whether the intervention shifted the value loop as
  expected

## Escalate or Stop When

- retention is reported without a value moment definition
- cohort splits are unavailable but strong claims are still being
  made
- the proposed fix touches acquisition messaging more than the
  product experience
- the team assumes churn reasons are uniform across segments

## Worked Scenario

- Week-three drop-off may come from approvers never returning
  after the first exception case, not from new-user confusion
  alone.
- Retention diagnosis should therefore inspect repeat value for
  secondary actors, not just the primary admin journey.
- That changes the intervention list materially.
