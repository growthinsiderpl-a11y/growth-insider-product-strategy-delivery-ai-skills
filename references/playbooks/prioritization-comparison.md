# Prioritization Comparison

Compare candidate initiatives using criteria and weights chosen
explicitly for the current decision rather than hidden defaults.

## When To Run It

- multiple product options compete for the same capacity
- the team needs transparent trade-off logic
- stakeholders disagree on what matters most
- a roadmap or board review needs a defendable ranking

## Do Not Run It When

- leaders want a fake objective answer from a canned framework
- there is only one obvious option and the real issue is execution
  quality
- scores cannot be justified from evidence or reasoned assumptions
- the comparison is being used to conceal a pre-made political
  choice

## Inputs

- option list
- criteria with weights
- reasoning or evidence for each option
- capacity constraints
- dependency notes
- decision date

## Procedure

### Choose Criteria

- pick criteria that reflect the decision context such as customer
  value, strategic fit, reversibility, dependency load, or time to
  learning
- write why each criterion matters now
- ensure weights are visible and editable
- remove redundant criteria
- state who owns the weight choices

### Score Transparently

- score from evidence or labeled assumptions
- add short rationale next to each score
- mark unknowns rather than forcing precision
- avoid converting uncertainty into fake confidence
- flag criteria where stakeholder disagreement is likely

### Stress-Test the Ranking

- change the weight mix to test sensitivity
- highlight where small assumption changes flip the result
- identify one scenario in which the current winner would lose
- capture dependence on enabling work
- check whether the ranking still aligns with stated strategy

### Recommend Action

- name the preferred option and its conditions
- list what is deferred or rejected
- state the cost of delay for the top options
- note what evidence could change the ranking
- separate ranking confidence from delivery confidence

### Prepare Communication

- translate the table into a short narrative
- show that weighting was a conscious choice
- avoid overclaiming objectivity
- store the comparison for future review
- make future re-weighting easy when conditions change

## Decision Tests

- weights are explicit
- scores have rationale
- sensitivity is reviewed
- the output leads to a real decision
- priority logic survives basic challenge from another stakeholder

## Outputs

- weighted comparison table
- sensitivity note
- decision recommendation
- deferred options summary
- explanation note for leadership

## Failure Modes

- hiding politics inside weights
- assigning precise scores with no evidence
- using the model to avoid making a judgment call
- pretending the model will stay valid if strategy changes

## Review and Follow-through

- refresh weights when strategy changes
- feed the chosen option into roadmap sequencing
- keep rejected options visible with reasons
- record the assumptions most likely to force reprioritization

## Escalate or Stop When

- weights are hidden from the audience
- criteria overlap so heavily they double-count one argument
- ranking reverses under any realistic sensitivity test
- the comparison is being used after leadership already made the
  decision elsewhere

## Worked Scenario

- Compare activation redesign, governed approvals, and export
  tooling with visible weights for customer value, strategic fit,
  reversibility, and dependency load.
- A transparent model may favor approvals even if activation
  touches more accounts because the governed segment is the
  current strategic target.
- The artifact should explain that logic plainly.
